Dropping VehicleForm into your app

A practical walkthrough for the app embedding these components: installing the package, wiring auth, and handling new / edit + save / cancel. Everything here is about the props you pass and the callbacks you receive — nothing about how the component works inside.

The library gives you data-aware form components — VehicleForm and VehicleTypeForm. You hand each one a GraphQL endpoint, a way to authenticate, and (optionally) the id of a record to edit. It loads the record, renders the form, and saves changes back for you. You don't write queries, mutations, or a save handler.

1Installing the package

Install from a GitHub Release. The repo is public, so the tarball URL needs no token:
npm i https://github.com/entur/mui-comps-nmr/releases/download/v0.1.0/entur-mui-comps-nmr-0.1.0.tgz

Releases are listed at github.com/entur/mui-comps-nmr/releases. Each carries one .tgz asset plus a note recording which sobek schema it was built against. The package is not on the npm registry — npm i @entur/mui-comps-nmr returns a 404.

Upgrading means editing the URL. A URL install pins that exact URL in your package-lock.json, so ^0.1.0 ranges don't work and npm outdated will never tell you a new version exists. Watch the Releases page and bump the URL by hand. This is the cost of not being on a registry — the version scheme is already registry-ready, so if that changes, the install command is the only thing that changes.

Link it, for active development

Use this when you're changing the library and the host side by side. Re-run npm run build after each change — the host consumes dist/, not src/.

cd mui-comps-nmr && npm link
cd ../host-app     && npm link @entur/mui-comps-nmr
Linking is where “two Reacts” bites. React, MUI and Emotion are externalized from the bundle precisely so the host supplies one shared copy — but a symlinked package resolves them from its own node_modules, which reintroduces the duplicate. Dedupe on the host side (Vite: resolve.dedupe: ['react', 'react-dom', '@mui/material', '@emotion/react', '@emotion/styled']), or prefer the tarball. Symptoms are invalid-hook-call errors and MUI theme/styles not applying.

Peer dependencies

All of these are externalized from the build — the host must have them installed, and their major versions are pinned to match hathor.

PackageRangeNote
react, react-dom^19.1.0React 19 only.
@mui/material^7.0.2Every control is MUI v7.
@mui/icons-material^7.0.2
@mui/x-data-grid^8.29.1Loaded lazily, only when a grid field renders — but still required.
@emotion/react, @emotion/styled^11.14.0MUI's styling engine.
The GraphQL client is bundled. graphql-request and the slice of graphql it needs are compiled into dist/, so the host installs no GraphQL packages and the library never touches your Apollo/urql client or its cache.

2Import & the shape of a form

Both components are named exports. They render the fields plus — in edit mode — their own Save button. You place the component wherever you want the form to appear.

import { VehicleForm, VehicleTypeForm } from '@entur/mui-comps-nmr';

<VehicleForm
  endpoint="https://sobek.example/graphql"
  getHeaders={authHeaders}
  netexId="VEH:Vehicle:123"
/>

Props you'll use

PropTypeWhat it's for
endpoint requiredstringThe GraphQL URL to load from and save to.
netexIdstringThe record to load and edit. Omit it at mount to start a blank “new” form (§5).
headersRecord<string,string>Static request headers (fixed API keys, tenant ids…).
getHeaders() => headers \| Promise<headers>Headers computed at request time — use this for auth tokens (see §3).
mode'view' \| 'edit'Default 'edit'. 'view' disables every input and hides Save.
onSaved(netexId) => voidCalled after a save succeeds; receives the saved record's id.
onError(msgs: string[]) => voidCalled with general (non-field) error messages when a save fails.
layout, variant, slotProps—Presentation only — which fields/sections show, tabs vs stacked, MUI overrides. Covered in the README.
Field-level errors are handled for you. When a save fails validation, the offending inputs show their messages inline automatically. onError only receives the general messages that don't belong to a single field, so you can show a banner or toast. If a save fails with no usable GraphQL error payload (network drop, malformed response), you still get one message: ['Failed to save'].
onError is save-only, and loads currently fail quietly. While the initial load is in flight the component renders a bare Loading... placeholder; if that load fails, nothing calls onError and no message reaches the UI — you get an empty form. If a failed load must be visible in your app, verify the record exists before mounting the form, or wrap it in your own error boundary/state.

3Authentication

You have two ways to attach credentials. Pick based on whether the value is fixed or has to be fetched fresh each time.

headers — fixed values

A plain object, sent as-is on every request. Good for things that never change during the session. An inline object literal is fine — see §4:

<VehicleForm endpoint={endpoint} headers={{ 'X-Tenant': 'entur' }} />

getHeaders — tokens & anything async

A function the component calls to obtain headers right before it needs them. It may return the object directly, or a Promise — so it fits token providers that refresh in the background. This is the right home for an Authorization header.

// e.g. with react-oidc-context or your own auth hook
const auth = useAuth();

<VehicleForm
  endpoint={endpoint}
  getHeaders={async () => ({
    Authorization: `Bearer ${await auth.getAccessToken()}`,
  })}
  netexId={id}
/>
You can use both. When you pass headers and getHeaders together, they're combined — getHeaders wins on any key it also sets. So put constants in headers and the token in getHeaders.

4Reloads — what triggers one

A reload replaces whatever the user was editing with freshly-loaded server values, so it matters which props can cause one. The list is short:

Prop changesEffect
netexIdReloads that record (or, if it becomes undefined, retires the in-flight load — see §5).
endpointNew client, reloads.
headers / getHeadersNothing. They're read fresh on every request, not watched.
Inline headers/getHeaders literals are safe. The component reads them per request rather than treating their identity as a dependency, so a new object or closure on every render costs nothing — no re-authentication, no reload, no lost edits. You do not need useCallback, useMemo, or module-scope constants here.

Because getHeaders is called immediately before each request, a token that refreshes in the background is always picked up — no prop change needed.

The flip side: changing auth won't reload the record. Since these props aren't watched, swapping tenant or credentials mid-session leaves the currently-loaded record on screen; only the next request uses the new headers. If a header change should mean “different data,” force it yourself with a key bump (§5).

5New, Save, and Cancel

These three host actions map onto the interface as follows. Note that Save is built in — you don't render or trigger it; you react to its result.

🆕 New

mount without netexId

Mount the form without a netexId and you get a blank create form. On save, onSaved hands you the id of the newly created record.

💾 Save

built-in button + onSaved

In edit mode the component shows its own Save button and performs the save. You listen with onSaved(id) for success and onError(msgs) for general failures.

↩︎ Cancel / discard

remount with a key

There's no cancel button. Edits live inside the form, so to throw them away you remount the component — change its React key, or navigate away. A remount reloads a clean copy.

New

// blank form → create a Vehicle
<VehicleForm endpoint={endpoint} getHeaders={getHeaders} mode="edit" />

// tell the host when it's been created
<VehicleForm
  endpoint={endpoint}
  getHeaders={getHeaders}
  onSaved={(newId) => navigate(`/vehicles/${newId}`)}
/>
Clearing netexId on a mounted form does not blank it. Going from an id to undefined only abandons the in-flight load — the values already on screen stay, deliberately, so an edit in progress is never wiped. To actually get an empty create form from a form that was showing a record, remount it: key={netexId ?? 'new'}.

Save

You don't call save. The user clicks the built-in button; you respond to the outcome:

<VehicleForm
  endpoint={endpoint}
  getHeaders={getHeaders}
  netexId={id}
  onSaved={(id) => {
    toast.success('Saved');
    refetchVehicleList();     // the record is now stale in your list
  }}
  onError={(msgs) => toast.error(msgs.join('\n'))}
/>
After onSaved, re-pull any of your own copies of the record. The form shows the freshly-saved values itself, but a list or header elsewhere in your app won't know it changed until you refetch it.

Cancel / discard

Because the form owns the in-progress edits, “cancel” means “give me a fresh copy.” Drive it with a key — bumping the key remounts the form and reloads:

function EditPane({ id }) {
  const [rev, setRev] = useState(0); // bump to discard edits

  return (
    <>
      <VehicleForm
        key={`${id}:${rev}`}      {/* new key ⇒ reload clean */}
        endpoint={endpoint}
        getHeaders={getHeaders}
        netexId={id}
        onSaved={() => toast.success('Saved')}
      />
      <button onClick={() => setRev(r => r + 1)}>Cancel</button>
    </>
  );
}
Use key when switching records, too. Setting key={netexId} (or netexId ?? 'new') guarantees that moving from one record to another — or from a record to a blank “new” form — starts clean, with no chance of one record's edits bleeding into the next.

6Read-only (view) mode

Pass mode="view" to show the same fields with every input disabled and no Save button — useful for a details pane or a permission-gated screen.

<VehicleForm endpoint={endpoint} getHeaders={getHeaders}
             netexId={id} mode="view" />

Flip mode between 'view' and 'edit' to toggle an edit affordance in your own toolbar.

7A complete host page

List on the left, form on the right. Auth from your app's hook, key for clean switching, view↔edit toggle, and a cancel that discards.

import { useState } from 'react';
import { VehicleForm } from '@entur/mui-comps-nmr';
import { useAuth } from './auth';

const ENDPOINT = 'https://sobek.example/graphql';

export function VehiclesPage({ vehicles, refetchList }) {
  const auth = useAuth();
  const [selected, setSelected] = useState<string | undefined>();
  const [mode, setMode] = useState<'view' | 'edit'>('view');
  const [rev, setRev] = useState(0);

  // no memoization needed — read per request, never a reload trigger
  const getHeaders = async () => ({
    Authorization: `Bearer ${await auth.getAccessToken()}`,
  });

  const discard = () => setRev(r => r + 1);

  return (
    <div style={{ display: 'flex', gap: 24 }}>
      <nav>
        <button onClick={() => { setSelected(undefined); setMode('edit'); }}>
          + New vehicle
        </button>
        {vehicles.map(v => (
          <button key={v.netexId} onClick={() => { setSelected(v.netexId); setMode('view'); }}>
            {v.name}
          </button>
        ))}
      </nav>

      <section>
        <header>
          {mode === 'view'
            ? <button onClick={() => setMode('edit')}>Edit</button>
            : <button onClick={() => { discard(); setMode('view'); }}>Cancel</button>}
        </header>

        <VehicleForm
          key={`${selected ?? 'new'}:${rev}`}   {/* clean switch + discard */}
          endpoint={ENDPOINT}
          getHeaders={getHeaders}
          netexId={selected}                    {/* undefined ⇒ new */}
          mode={mode}
          onSaved={(id) => {
            setSelected(id);
            setMode('view');
            refetchList();                        // keep the list fresh
          }}
          onError={(msgs) => alert(msgs.join('\n'))}
        />
      </section>
    </div>
  );
}

8Checklist

  • install npm i https://github.com/entur/mui-comps-nmr/releases/download/v0.1.0/entur-mui-comps-nmr-0.1.0.tgz — no token. Upgrades are manual URL edits. Host supplies React 19 / MUI 7 / x-data-grid 8 / Emotion 11.
  • endpoint Always required — your GraphQL URL.
  • auth Token → getHeaders (may be async); constants → headers. Both allowed.
  • stable No memoization needed — inline headers/getHeaders literals are safe; they're read per request, not watched. Only netexId and endpoint trigger a reload.
  • new Mount without netexId for a blank create form; get the new id from onSaved. Clearing netexId on a live form keeps its values — remount to blank it.
  • save Built in — the component renders its own Save button; you react via onSaved / onError.
  • cancel No cancel prop — remount via key to discard edits and reload.
  • key Set key={netexId ?? 'new'} so switching records always starts clean.
  • refresh After onSaved, refetch any list/header copies of the record you keep.
  • view mode="view" disables inputs and hides Save.
  • load onError covers saves only — a failed load is silent. Handle it yourself if it matters.
